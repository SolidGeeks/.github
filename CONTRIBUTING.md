# Contributing to Solid Geeks

We build free software and hold it to professional standards. Your first pull request is welcome, and someone will help you land it.

## Your first reps

1. **Say hi** on the Discord (link on [our site](https://solidgeeks.github.io/SolidGeeks/)).
2. **Pick an issue** labelled [`good first issue`](https://github.com/search?q=org%3ASolidGeeks+label%3A%22good+first+issue%22+state%3Aopen&type=issues). Comment to claim it.
3. **Fork, branch, code.** Keep the change small and focused.
4. **Sign off every commit** with `git commit -s`. This certifies the [Developer Certificate of Origin](https://developercertificate.org/). You keep your copyright; there is no CLA.
5. **Open a pull request** and fill in the checklist. A maintainer reviews it with you.

## The Solid standard

Every repository in the organization keeps these promises:

- A license from our policy, with SPDX headers in source files
- Tests run in CI on every pull request
- A `SECURITY.md` with a private way to report
- Signed releases and a readable changelog
- Docs a newcomer can follow to a first run
- Commits signed off under the DCO

## Reviews

Reviews are about the code, never the person. Expect questions; ask them too.

Every change, maintainers' included, goes through a pull request: `main` cannot be pushed to directly, and a pull request merges only once CI and the DCO check pass. While Solid Geeks has a single maintainer, no approval is required. Once the project has more maintainers, changes to core projects will need two approvals, and docs one.

## Conduct

Read the [Code of Conduct](CODE_OF_CONDUCT.md). Short version: lift each other up.
